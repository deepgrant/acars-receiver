# ACARS Receiver

Receive traditional VHF ACARS with an RTL-SDR on the Mac Studio M1 Max and
preserve decoded JSON for a future UI. The Raspberry Pi ADS-B feed uses its
own receiver.

The Groovy Gradle build follows the `pidex` project's task structure: native
configuration and compilation, staging, verification, installation, and
distribution are separate tasks. The checked-in wrapper and wrapper JAR are
generated by **Gradle 9.8.1**, with the official distribution checksum pinned.
No system Gradle installation is required. Java **17 or later** is required.

## Build and run

For a fresh checkout on an Apple Silicon Mac, install Apple Command Line
Tools and Homebrew's `cmake`, `pkg-config`, `libusb`, and `cjson`, then run:

```bash
git clone https://github.com/deepgrant/acars-receiver.git
cd acars-receiver
./gradlew build
./gradlew checkSdr
./gradlew receive
```

`build` compiles and verifies the decoder, runs simulated capture tests,
installs the portable bundle under `outputs/acars-macos-arm64/`, and creates
`outputs/acars-macos-arm64.tar.gz`. Installation replaces program files
atomically and preserves open file handles held by a running receiver.
The build never opens the SDR. `receive` builds
the bundle if needed, then displays ACARS messages and writes daily JSON.
Stop reception with Control-C. `run` is an alias for `receive`.
Stop any existing program using the dongle before starting a new receive or
capture task.

The build is incremental. An unchanged build skips source checkout, CMake
configuration, compilation, staging, signature verification, and installation.
CMake retains its own object-file incrementality when native sources change.
Machine-specific native artifacts are not shared through the Gradle build cache.

The standalone bundle's `start-acars.command` still runs without Java, Gradle,
Homebrew or Xcode. The project's root `start-acars.command` is a shortcut to
`./gradlew receive`, and the old `work/acars-macos/build-macos.sh` delegates to
`./gradlew buildReceiver`.

## Receiver settings

The RTL-SDR Blog V4 defaults are **0 ppm, gain 49.6 dB, bias tee off**. Use
the long telescopic elements, approximately 55 cm per arm, mounted vertically
near a window. The saved gain is a tested starting setting, not a measured optimum.

```bash
./gradlew receive -Pfrequencies=131.550
./gradlew receive -Pdevice=1 -Pgain=40.2 -Pstation=MY-STATION
./gradlew receive -Pppm=50
```

The +50 ppm correction is specifically for the previously calibrated NESDR
Mini; keep the V4 at 0 ppm. With multiple dongles, explicitly select the spare
receiver using `-Pdevice=<index-or-serial>`. Hardware tasks do not choose among
multiple dongles automatically.

Project properties take precedence over the existing `ACARS_GAIN`, `ACARS_PPM`,
`ACARS_STATION` and `SDR_DEVICE` environment variables. `frequencies` accepts
comma- or space-separated MHz values. The default ten channels are 130.025,
130.450, 130.825, 130.850, 131.125, 131.525, 131.550, 131.725, 131.825 and
131.850 MHz.

For a bounded live test:

```bash
./gradlew capture -PcaptureSeconds=120 -PcaptureName=v4-test
```

`capture` stops only the decoder it starts, reports newly received messages,
and fails if the decoder fails. A quiet capture with no messages is allowed.
It saves `outputs/acars-macos-arm64/data/v4-test.jsonl`. Continuous logs are
`outputs/acars-macos-arm64/data/acars_YYYYMMDD.jsonl`; timestamps and rotation use UTC.

## Tasks

| Task | Purpose |
| --- | --- |
| `fetchSources` | Fetch pinned native source revisions and apply the macOS patch. |
| `configureRtlSdr`, `compileRtlSdr`, `installRtlSdr` | Build the V4-capable driver in a private prefix. |
| `configureAcarsdec`, `compileAcarsdec` | Build the decoder with RTL input and JSON output. |
| `compileDeviceProbe` | Build the read-only receiver enumeration helper. |
| `sourcesArchive` | Archive corresponding native sources without Git metadata. |
| `stageReceiver`, `verifyReceiver` | Relocate libraries, sign and verify the standalone bundle. |
| `installReceiver` | Copy verified program files while preserving reception logs. |
| `receiverArchive` | Create the portable archive without live data. |
| `buildReceiver` | Build, verify, install and archive; does not run capture tests. |
| `test` | Test capture lifecycle and device selection using fake executables. |
| `verifyWrapper` | Check the wrapper JAR against the official Gradle 9.8.1 checksum. |
| `checkSdr`, `receive`, `capture` | Explicit hardware operations; never dependencies of `build` or `test`. |
| `clean` | Remove Gradle-owned native sources, caches and staging under `build/`. |

`clean` preserves the installed standalone bundle and all reception data in
`outputs/`. Source pins and the macOS deployment target are in `gradle.properties`.
The native build currently targets Apple Silicon and macOS 15 or newer.
`--offline` works after the wrapper and source checkouts have been downloaded.
Use `-PnativeJobs=4` to limit compiler jobs, `-PhomebrewPrefix=/opt/homebrew` to
override the dependency prefix, or `DEVELOPER_DIR` to select another toolchain.
The default developer directory is the standalone Command Line Tools, avoiding
changes to the Mac's global Xcode selection.

## Layout and verification

- `build.gradle`, `buildSrc/`: task graph and the source/install task implementations.
- `Scripts/`: small helpers for macOS binary relocation, verification, bounded
  process control, and the standalone launcher's shell interface.
- `src/native/`, `patches/`, `src/dist/`: device probe, macOS patch and bundle README.
- `build/`: Gradle-owned checkouts, CMake outputs and staging; ignored by Git.
- `outputs/acars-macos-arm64/data/`: preserved live JSON; ignored by Git.
- `docs/setup-history.md`: hardware calibration and reception history.

V4 live reception was verified on October 12, 2026: four messages from N584QS
on 131.725 MHz, all with zero reported parity errors, including airport-status
and position messages. The UI, database, VDL2 receiver and Pi 4 deployment
remain TBD.

Upstream projects: [acarsdec](https://github.com/f00b4r0/acarsdec) and
[rtl-sdr](https://github.com/osmocom/rtl-sdr). Their licenses and corresponding
source snapshots are included in the portable bundle. Live captures and build
outputs are excluded from Git and from the distribution archive.
